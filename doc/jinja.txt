1. About                                                         *jinja-about*

Neovim plugin for treesitter highlighting of Jinja templates, including custom
delimiters.

Jinja allows changing tag delimiters (e.g. Copier’s `_envops` or
Cookiecutter’s `_jinja2_env_vars`), but treesitter jinja parser supports only
default ones. This plugin highlights both kinds of templates, together with the
language of the template output (inner language) detected by file name without
`.jinja` (e.g. `config.yml.jinja`).


==============================================================================
2. Features                                                   *jinja-features*

- Templates get filetype `<inner>.jinja` (e.g. `yaml.jinja`),
    so inner language features keep working like in usual files:
    its ftplugin, treesitter highlighting, folds, indentation, textobjects, etc.
- Jinja tags are hidden from inner language parser and highlighted on top of it.
- Custom delimiters are configured per directory.
- Whole Jinja tags are captured as `@jinja.tag` (e.g. to add a background).
- Templates without known inner language get filetype `jinja`
    and `commentstring` set to Jinja comment.
- Starts treesitter highlighting by itself.


==============================================================================
3. Requirements                                           *jinja-requirements*

- Neovim 0.12+.
- Treesitter parsers and highlight queries for `jinja`, `jinja_inline` and inner languages,
    e.g. installed by nvim-treesitter <https://github.com/nvim-treesitter/nvim-treesitter>.

4. Installation                                           *jinja-installation*

Install the plugin with your preferred package manager. The plugin loads its
modules only when needed, so it should not be lazy-loaded.


LAZY.NVIM                                       *jinja-installation-lazy.nvim*

>lua
    return {
        'powerman/jinja.nvim',
        opts = {
            -- Your configuration here, if any.
        },
    }

5. Setup                                                         *jinja-setup*

You should call `setup()` only if you need custom delimiters (package managers
configured as shown above will do this for you). It must be called before
opening templates, because it affects filetype detection.

>lua
    require('jinja').setup {
        -- Your configuration here, if any.
    }
<


==============================================================================
6. Configuration                                         *jinja-configuration*

>lua
    ---@type JinjaConfig
    local defaults = {
        -- Custom delimiters for templates inside directories matching `dir` glob.
        -- The first matching entry wins.
        delimiters = {
            -- {
            --     dir = '~/Templates/copier-*', -- Matches all subdirectories too.
            --     -- Start and end strings, not set ones keep default values.
            --     -- Custom delimiters can't be shorter than default ones.
            --     block = { '{%', '%}' },
            --     variable = { '{{', '}}' },
            --     comment = { '{#', '#}' },
            -- },
        },
    }
<

Example. Copier templates with `_envops` changing delimiters to look like
comments in YAML, TOML, shell scripts, etc.:

>lua
    require('jinja').setup {
        delimiters = {
            {
                dir = '~/Templates/copier-*',
                block = { '#{', '}#' },
                variable = { '#=', '=#' },
                comment = { '#%', '%#' },
            },
        },
    }
<

7. Highlighting                                           *jinja-highlighting*

Tokens inside Jinja tags are highlighted with usual treesitter groups like
`@keyword.jinja`. Whole Jinja tags are captured as `@jinja.tag` group, which is
not defined by default. Define it to make tags stand out, e.g. with a
background. Like other highlight groups it is cleared on loading a color
scheme, so define it in your color scheme config or in a `ColorScheme`
autocommand created before loading a color scheme:

>lua
    vim.api.nvim_create_autocmd('ColorScheme', {
        callback = function()
            vim.api.nvim_set_hl(0, '@jinja.tag', { bg = '#2a3448' })
        end,
    })
<

Example. Use a light background for tags with tokyonight.nvim
<https://github.com/folke/tokyonight.nvim>:

>lua
    require('tokyonight').setup {
        on_highlights = function(hl, c)
            hl['@jinja.tag'] = { bg = require('tokyonight.util').blend_bg(c.cyan, 0.15) }
        end,
    }
<

8. Other tools                                             *jinja-other-tools*

Plugins supporting compound filetypes (e.g. conform.nvim, nvim-lint) use tools
of the inner language for templates, but these tools don’t know about Jinja
tags. E.g. formatters may fail or break formatting of tags, and linters may
report errors for tags.

With conform.nvim <https://github.com/stevearc/conform.nvim> formatters can be
disabled for templates by a function (an empty table is ignored and formatters
of the inner language are used instead):

>lua
    require('conform').setup {
        formatters_by_ft = {
            jinja = function()
                return {}
            end,
        },
    }
<

LSP servers and `FileType` autocommands work only for exact filetypes, so to
use them for templates add template filetypes to their configs, e.g.:

>lua
    vim.lsp.config('yamlls', { filetypes = { 'yaml', 'yaml.jinja' } })
<


==============================================================================
9. Limitations                                             *jinja-limitations*

- Inner language parser sees the text without Jinja tags,
    so a tag used as a value may break inner language syntax (e.g. `k = {{ x }}` in TOML).
- Unlike Jinja, end delimiter inside a string in a tag (e.g. `{{ '}}' }}`) ends the tag.
- Line statements and line comments (disabled in Jinja by default) are not supported.
- Indentation of Jinja blocks is not provided.
- Inner filetype detection by content uses the template text,
    e.g. a file without extension with lines starting with `#` is detected as `conf`.
